## Naming Convention

| Prefix | Role | Externally referenceable? |
|--------|------|--------------------------|
| `tpl_generic_<type>` | Fallback template per task type (SENSOR, MATH, ACTUATOR, CONTROL, GENERATOR). Used automatically when no specific view is configured. | Yes (automatic fallback) |
| `tpl_<name>` | Reusable view components, **task-type independent**. These are the building blocks for `views[]` arrays. A `tpl_scope` can appear in a SENSOR, MEASURE, or GENERATOR task. | **Yes** — use freely in any manifest |
| `system_<name>` | Self-contained plugin UIs that manage their own rendering. Tightly coupled to a specific plugin. Not intended to be referenced by external tasks. | No — internal only |

### Quick Reference for Plugin Developers

```
"Which views can I assign to my task?"

→ Use any tpl_* template in your views[] array:
  tpl_scope              Time-domain graph
  tpl_metric             SI auto-range metric display
  tpl_spectrum           FFT frequency-domain graph
  tpl_spectrum_config    Spectrum settings panel
  tpl_device_config      Generic configuration panel

→ If you don't specify views, the system uses tpl_generic_<your_task_type>
```

### Registering a `system_*` Template

Plugins that provide their own UI (e.g. FIR Filter, Mean) need a **separate
template export** so the `PluginRegistry` can resolve the template ID.
The plugin ID (`system_*_v1`) and the template ID (`system_*`) are intentionally
different — the plugin owns the task lifecycle, the template owns the rendering.

```jsx
// 1. Plugin with createTask + simulation (plugin ID = system_example_v1)
export const ExamplePlugin = new PluginBuilder("system_example_v1", "Example", "MATH")
    .setRender(ExampleWidget)
    .setCreateTask(() => ({
        id: `example_${Date.now()}`,
        groupId: "system_example_v1",
        type: "MATH",
        name: "Example",
        ui: {
            mode: "generic",
            defaultTemplate: "system_example",  // ← references the template below
            views: [
                { id: "config", label: "Config", icon: "Settings", template: "system_example" },
            ],
        },
    }))
    .build();

// 2. Separate template export (template ID = system_example)
export const ExampleTemplate = {
    id: "system_example",
    name: "Example Config",
    type: "UI_TEMPLATE",
    render: ExampleWidget,
};
```

> **Note:** `system_*` views can also reference `tpl_*` templates in their
> `views[]` array (e.g. `tpl_metric` for a numeric display alongside a custom config view).
